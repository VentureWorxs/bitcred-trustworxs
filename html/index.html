SD-JWT credential demo

Each run issues a membership credential (synthetic data) bound to a holder key, presents two of its five claims to a verifier, and then tries five attacks. Everything runs in this Worker; nothing is stored.

Key binding is opt-in. With @sd-jwt/sd-jwt-vc, verify() skips the holder check unless you pass keyBindingNonce and expectedKeyBindingAudience. A stolen credential with no key-binding JWT is then accepted. The strict verifier used below sets both and requires the key-binding JWT.
